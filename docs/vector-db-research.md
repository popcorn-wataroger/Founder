# ベクトルDB運用方針の調査

## 目的

Founder のベクトルDB（Qdrant）を、本番環境（GCP デプロイ）でどう運用するかを検討する。
コスト・管理のしやすさの観点で選択肢を比較し、方針を決める。

## 前提：Founder の規模

- 社員数：100人以下
- 対象データ：社内資料（業務マニュアル、PDF、規定など）
- ベクトル数の目安：社内資料を100ファイルほどアップしても 5〜10万ベクトル程度
  （※ベクトルは「資料を細かく区切ったチャンク」1つにつき1個。資料1ファイル≠1ベクトル）

## 検討した選択肢

### A. GCP上で Qdrant を自前運用
GCE（Compute Engine＝仮想サーバー）に Qdrant をインストールして動かす。

### B. Qdrant Cloud（マネージドサービス）
Qdrant 社が提供するクラウド。サーバー管理を Qdrant 側に任せる。無料枠あり。

### （参考）C. Vertex AI Vector Search
GCP 純正のベクトル検索サービス。ただし Qdrant とは別物のため、検索まわりのコードを
大幅に書き換える必要がある。今回は Qdrant を使う前提のため検討から除外。

## 課金の仕組み（重要な前提）

Qdrant は **リクエスト数では課金されない**。RAM・CPU・ディスクといった
**リソースに対して課金**される。そのため「リクエスト何件で〇〇円」という形では
比較しにくい。

## コスト比較（Founder 規模）

※ 金額は1ドル＝150円換算の概算。GCP自前運用は最小構成（e2-small）での試算値。

| | A. GCP自前運用 | B. Qdrant Cloud |
|---|---|---|
| MVP段階（5〜10万ベクトル） | 月約1,800円〜（最小構成での試算） | 0円（無料枠内） |
| 課金の単位 | サーバー稼働時間 | リソース使用量 |
| リクエスト数の影響 | なし | なし |

### B. Qdrant Cloud（無料枠）の内訳
- 無料枠：0.5 vCPU / 1GB RAM / 4GB ディスク（**永久無料**）
- Founder 規模なら無料枠の上限（約100万ベクトル）の1割未満に収まる
- リソースが上限内であれば 0円/月

### A. GCP自前運用の内訳
- **GCE（仮想サーバー）の料金**：e2-small（2GB RAM）で月約12ドル（約1,800円）
  - これは24時間×30日 稼働させた場合
- **ストレージ**：GCE に付ける永続ディスク（Persistent Disk）を使用
  - ※ GCS（ファイル置き場）ではなく、永続ディスクが適切
  - ※ 永続ディスク代は別途かかる（容量に応じた従量課金）
- 構成：GCEサーバー代（月約1,800円〜）＋ 永続ディスク代（別途）

> 注意点：100万ベクトル（1536次元）を扱うには約8GB RAM が必要という情報がある。
> Founder はそこまで大きくないため 2GB でも動く可能性は高いが、最小構成だと
> ギリギリになる可能性がある。実際の必要スペックは構築時に要確認。

## 管理面の比較

| | A. GCP自前運用 | B. Qdrant Cloud |
|---|---|---|
| 始めやすさ | サーバー構築が必要 | コード変更は接続先URLのみ |
| 長期的な運用 | GCP内で完結し統一できる | 外部サービスを別途監視・連携する手間が継続的に発生 |
| 障害対応 | 自前 | Qdrant側が対応 |

## 結論（現時点）

- **コストだけ**見れば Qdrant Cloud が有利（MVP段階は無料）
- ただし Qdrant Cloud は外部サービスのため、**別途監視・連携する運用負荷が継続的に発生**する
- この運用負荷は金額に表れない部分
- 開発案件としてインフラ費用が許容範囲であれば、**長期的な管理のシンプルさを重視して GCP で統一する**方向が理にかなう
- 最終方針はチームで判断

## 判断の過程・気づき

最初は「コストが安く、サーバー管理も不要」という理由で Qdrant Cloud を推していた。

ただ、藤田さんから「Qdrant Cloud を別途監視する手間・繋がないといけない手間がある」という指摘をいただき、**外部サービスを抱えることの運用負荷を完全に見落としていた**ことに気づいた。

コストの安さだけに目を向けすぎていて、「継続的にかかる運用の手間」という金額に表れないコストを考慮できていなかった。

また、エンジニアの工数コストはインフラ費用より高くつく場合が多いという観点も、今回初めて意識できた。「月1,800円を節約しても、管理に毎月数時間かかれば、人件費の方がずっと高くつく」という判断軸は、IT業界では当然の考え方だが、最初は持てていなかった。

これらの気づきを踏まえると、コストが許容範囲内であれば GCP で統一する方が、長期的には合理的な判断だと理解した。
